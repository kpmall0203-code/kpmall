# 아마존 광고 자동화 — 구현 현황 인수인계서

작성 2026-09-07 · 저장소 `kpmall0203-code/kpmall` · 가지 `claude/spreadsheet-manipulation-qysp1q`

이 문서의 목적은 하나다. **다른 설계자가 트랙 A·B 기획서를 처음부터 다시 쓸 수 있도록,
지금 있는 것·재본 것·겪은 것을 있는 그대로 적는다.** 지금 설계를 팔지 않는다.
어디가 약한지는 13장에 따로 적었다.

표기: **[사용자]** 는 판매자가 정한 제약이라 새 설계도 지켜야 하는 것.
**[설계]** 는 내가 고른 것이라 바꿔도 되는 것.

## 0. 한 장 요약

- 아마존 일본 셀러. SKU 약 7,700 · 리스팅 약 26,000 · 마진율 15~20%(기본 17%).
- 구글 스프레드시트에 붙은 Apps Script 하나가 전부다. 아마존 광고 API v3 (Sponsored Products) 를 부른다.
- 트랙이 둘이다.
  - **트랙 A (재배분)** 이미 팔리는 상품에 마진 안에서 노출을 산다. 손해를 허용하지 않는다.
  - **트랙 B (육성)** 새 상품에 일부러 정한 만큼 손해를 보며 검색어 순위를 산다.
- 둘 다 **채산성에서 판단**한다. 광고 이력으로 판단하지 않는다 — 제대로 광고해 본 SKU 가 없다.
- 층이 셋이다. **수집**(API → 시트) · **판단**(시트 → 시트) · **실행**(시트 → API 쓰기).
  실행 단계에서 API 를 읽으면 6분 한도에 걸린다. 실제로 네 번 걸렸다.
- 트랙마다 계획 표가 따로 있고(광고생성계획 · 광고육성계획), 생성·켜기·멈춤·관제·대장은 한 벌이 표 목록을 돈다.
- 돈이 나가는 스위치(켜기·키워드 올리기·부정 키워드)는 줄마다 사람이 ✓ 한 것만.
- 관제가 매일 08시 트랙마다 주간 한도를 보고 넘친 트랙만 멈춘다.
- 2026-09-07 현재: 트랙 A 캠페인 86개 만들어짐(켜진 것 3), 트랙 B 캠페인 3개 오늘 만들어 켜짐.

### 1.2 사용자가 정한 것 — 새 설계도 지켜야 한다
- **[사용자]** 원가·마진율·오가닉 순위는 사람이 준다. **추정하지 않는다.**
- **[사용자]** 현존하는 광고 데이터로 구조를 잡지 않는다 ("현존하는 데이터로 구조를 잡으려고 하면 필패").
- **[사용자]** 새 상품이 나중에 들어와도 이미 있는 캠페인에 들어가도록, 규칙이 재사용 가능해야 한다.
- **[사용자]** 한 번에 한 걸음. 검증하고 다음으로.
- **[사용자]** 대장은 사람이 읽을 수 있게, SKU·ASIN 과 함께.
- **[사용자]** 진행 상태가 보여야 하고, 재시도가 있어야 하고, 오류 기록과 함께 중단돼야 한다.
- **[사용자]** **수집과 실행을 가른다.** 실행은 시트를 읽고 API 에 쓴다. 실행 중 API 읽기는 타임아웃이다.
- **[사용자]** 기획서를 두고 코드를 짜기 전에 읽는다 (문맥이 한정된 작업자를 위해).
- **[사용자]** 줄임말을 쓰지 않는다. 시트 머리글도 말로 (`N` → `판정필요클릭`).
- **[사용자]** 돈이 나가는 스위치는 줄마다 명시적 승인.
- **[사용자]** 트랙 B 는 바깥 마진율 시트를 읽지 않는다. 몇 개뿐이니 시트에 직접 적는다.
- **[사용자]** 트랙 B 주간 예산은 SKU 마다 따로. 관제는 B 값을 더하기만 하고 A 의 한도에 섞지 않는다.
- **[사용자]** 트랙 A 와 B 의 시트를 따로 둔다 (2026-09-07, 겹쳐 쓰다 오류가 나서).
- **[사용자]** 이미 1페이지에 있는 상품은 트랙 B 대상이 아니다.

## 3. 아마존 API 에서 확인한 사실 — 설계를 제약한다

1. **자동(AUTO) 캠페인에는 키워드를 넣을 수 없다.** 겨냥(targeting clause)만 받는다. 부정 키워드는 자동·수동 둘 다 된다.
   → 승격(판 검색어를 키워드로 올리기)은 반드시 **수동 캠페인이 따로** 있어야 한다.
2. **캠페인 유형(AUTO ↔ MANUAL)은 만든 뒤 바꿀 수 없다.** 새 캠페인을 만드는 수밖에 없다.
3. **검색어 리포트(spSearchTerm)는 캠페인·광고그룹까지만 준다.** 어느 SKU 가 팔았는지는 알 수 없다.
   그룹에 SKU 가 하나면 답이 하나라 알 수 있고, 여럿이면 모른다.
4. **캠페인·광고그룹 이름은 아스키만.** 한글은 통째로 거부된다. 조용히 걷어내는 fallback 을 뒀더니
   '사입' 이 'KP' 로 바뀌어 사용자가 놀랐다 — 실패보다 조용한 대체가 더 나쁘다.
5. **자동 캠페인의 겨냥 넷.** 각각 상태·입찰을 따로 줄 수 있다 (`/sp/targets`).
   ```
   QUERY_HIGH_REL_MATCHES   유사검색어   내 리스팅 말과 가까운 검색어
   QUERY_BROAD_REL_MATCHES  넓은검색어   느슨하게 관련된 검색어
   ASIN_SUBSTITUTE_RELATED  대체상품     비슷한 남의 상품 페이지  ← 검색 결과가 아니다
   ASIN_ACCESSORY_RELATED   보완상품     같이 쓰는 남의 상품 페이지 ← 검색 결과가 아니다
   ```
6. **광고 매출은 클릭 후 14일까지 붙는다.** 최근 14일 안의 값은 '잠정'.
7. **리포트는 비동기.** POST `/reporting/reports` → 상태 폴링 → GZIP_JSON 내려받기. 한 실행에서 90초만 기다리고 넘으면 1분 뒤 다시 (4분을 기다리면 남은 시간에 쓰기를 못 한다).
8. **일괄 응답은 207.** `success`/`error` 배열이 따로 오고 `index` 로 되짚어야 한다. 보낸 순서와 온 순서가 같다는 보장이 없다.
9. **상품광고 목록**: 한 그룹에 1만 개 넘는 것이 있어 500개씩 200번 → 6분 초과. 그래서 그룹당 25개만 표본으로 받아 '작은가 큰가' 만 가른다 (`ADPROD_PROBE`=25, 전용 판정 기준 `ADPROD_DEDICATED_MAX`=5).
10. 한도: 최소 입찰 ¥2 · 최소 일예산 ¥100 · 검색어/키워드 80자 · 한 요청에 키워드 100개.
11. 아마존 ID 는 자릿수 많은 숫자꼴 문자열이다. 시트가 숫자로 바꾸면 뒷자리가 반올림돼 **다른 ID 가 된다.** ID 칸은 반드시 글자 서식(`@`).

## 4. 트랙 A — 재배분

### 4.1 계산식 (72H) — [설계]
```
손익분기 CPA = 객단가 × 마진율                 한 건 팔아 남는 돈
CPC 상한     = 손익분기 CPA × 오가닉 전환율     여기를 넘으면 팔수록 손해
권장 CPC     = CPC 상한 × 목표 ACOS 비율(0.65)  잠식 30% 까지 적자가 안 나는 선
필요 CVR     = CPC ÷ 손익분기 CPA               지금 값에 사서 본전이 되려면 필요한 전환율
판정필요클릭  = 3 ÷ 필요 CVR                     손익분기 주문 3건이 나왔어야 할 클릭 수
```
성질: `판정필요클릭 × CPC = 손익분기CPA × 3`. CPC 가 약분되어 **판정에 드는 돈은 언제나 '손익분기 주문 3건어치'** 다.

객단가·세션·오가닉전환율·카트박스는 `판매실적` 탭(판매 리포트)에서. 마진율은 원가가 있으면 실측, 없으면 광고기준의 기본값 또는 가격대별 값.

### 4.2 판정 규칙 (광고재배분 탭) — 위에서부터 먼저 걸리는 것
| 판정 | 조건 |
|---|---|
| 제외 | 재고 0 또는 리스팅 상태 Active 아님 |
| 성립 불가 | 마진 없음 |
| 판정 안 함 | 세션 < 200 — 전환율을 믿을 수 없다 |
| 제외 | 카트박스 < 90% — 전환 문제가 아니라 값 문제 |
| 성립 불가 | 오가닉 전환율 < 1% — 보여줘도 안 산다 |
| 성립 불가 | CPC 상한 ≤ 시장 CPC — 사면 살수록 손해 |
| 신규 캠페인 | 광고 안 하고 있음 |
| 캠페인 분리 | 광고 중이나 그룹에 SKU 가 5개 넘음 — 이 SKU 만 입찰을 못 바꾼다 |
| 인하 | 지금 입찰 > CPC 상한 |
| 인상 | 권장 > 지금 × 1.25 (한 번에 최대 3배까지) |
| 유지 | 나머지 |

표에는 인하·인상·캠페인 분리·신규 캠페인·성립 불가만 남긴다(나머지는 볼 것이 없어 가린다, 광고기준에서 켤 수 있음). 처음에 3,000행에서 잘랐다가 654행이 말없이 사라진 적이 있어 지금은 자르지 않는다.

### 4.3 캠페인 생성 계획 (72I → 광고생성계획) — [설계]
트랙 A 의 실행은 "입찰 조정" 이 아니라 **"값을 따로 매길 수 있는 그릇을 만드는 일"** 이다. 옛 그룹에는 SKU 가 1만 개라 하나만 올릴 수가 없다.

- **전용**: 오가닉 매출 상위 30 SKU 는 SKU 하나에 캠페인 하나. 이름 `KP <ASIN>` (ASIN 없으면 `KP SKU<해시>`).
- **묶음**: 나머지는 권장 CPC 가 비슷한 것끼리 최대 20개. 구간은 **고정** — 기준점 ¥2 에서 배수 1.5 로 쌓는다: 2 · 3 · 4.5 · 6.8 · 10 · 15 · 22 · 34 · 51 … 권장 ¥17 인 상품은 언제 들어오든 [15~22] 묶음. 이름 `KP B5 CPC15-23 #1` — 대조는 구간 번호(B5)와 순번으로만 한다 (읽을 거리는 반올림으로 바뀔 수 있어서).
- 묶음 입찰 = 구간 아래 끝 (묶였다는 이유로 손해 보는 상품이 없게).
- **바닥 규칙**: `입찰 = max(원래 입찰, 시장 CPC)`. 실제로 ¥5~7·¥7~10 구간 395개가 시장가 ¥7.7 아래로 입찰해 노출을 못 샀다. 딸려 올라가는 상품을 막으려고 담기 전에 거른다: `CPC 상한 ≥ 시장 CPC × 1.2` 인 SKU 만.
- **일예산** = `max(¥100, 손익분기CPA × 3 ÷ 14 × 여유배수 2.0)` 을 `월매출 × 마진율 × 0.65 ÷ 30` 안으로. 묶음은 그 묶음에서 가장 낮은 손익분기CPA.
- 이미 만든 캠페인은 광고그룹 탭에서 찾아 '기존에 추가' 로 (자리가 남으면 담고, 없으면 하나 더).
- 계획 다시 계산은 표를 통째로 다시 쓴다. 트랙 M(승격) 줄은 건져서 도로 붙인다. 이미 만든 줄의 결과·ID·승인은 이름으로 찾아 옮긴다.
- 마지막 실행 (2026-09-06): SKU 819개 · 새로 46 + 기존에 추가 40 + 건너뜀 29 · 하루 ¥7,097 · 시장가 못 넘어 뺀 SKU 72개(월매출 ¥13,201,520) · 바닥으로 올린 캠페인 30개.

### 4.4 실행 (72J)
- **생성**: 캠페인(AUTO/MANUAL 은 계획의 [유형] 칸) → 광고그룹(기본입찰) → 상품 등록 (받은 광고ID 를 [광고ID들] 에 저장) → 그 SKU 가 옛 그룹에 있으면 거기서는 멈춤(지우지 않는다). 멈춤 상태로 만들지 켜진 상태로 만들지 사람이 고른다.
- **켜기 — 승인 ✓ 만** / **승인대로 맞추기 — 미승인은 끔** / **전부 멈추기**. 세 메뉴가 서로 다른 동사다. 한 창에 두 동사를 넣었다가 사용자가 "기능이 안 됐나" 한 적이 있다.
  줄마다 갈 상태를 정하고(`adTargetState_`), 캠페인·광고그룹·상품광고를 함께 바꾼다. 결과 칸은 15줄마다 한 번 시트에 쓴다 (줄마다 쓰면 6분을 넘긴다).
- **승인분 입찰 반영**: 재배분 승인 ✓ 의 권장 CPC 를 그룹·키워드에. 한 그룹에 SKU 여럿이면 가장 낮은 권장가.

### 4.5 트랙 A 에 없는 것

## 5. 검색어 판정과 승격 — 두 트랙 공통

### 5.1 수집 (72L) — [설계]
- `spSearchTerm` 리포트를 **주 단위**로 받아 `광고검색어주간` 에 **덧붙이기만** 한다 (같은 주를 다시 받으면 그 주만 갈아끼움). 8주 보관.
- 다 받으면 검색어+광고그룹으로 합쳐 `광고검색어` 를 통째로 다시 만든다. 승인 ✓·반영결과·승격SKU·승격캠페인은 검색어+그룹 열쇠로 이어 붙인다.
- 처음에는 판정 표 하나에 주마다 얹고 전체를 다시 썼다. 4주에 123만 셀 → 타임아웃. 그래서 원본과 판정을 갈랐다.
- 한 주에 약 1만 줄. 리포트 열은 `campaignName`·`adGroupName`·`keyword`·`matchType` 을 넣어 보고 거절되면 단계적으로 줄인다 (이름은 광고구조에서 붙일 수 있다).

### 5.2 판정 (`adTermVerdict_`)
그룹의 채산성(손익분기CPA)은 그 그룹의 SKU 에서 오고, SKU 를 모르는 몰아넣기 그룹은 **그 그룹이 실제로 판 객단가 × 마진율** 로 (`[그룹 실적 기준]` 이라 표시, 한 단계 무른 근거).
```
판정 안 함   채산성을 모른다 (SKU 도 모르고 이 기간에 판 것도 없다)
승격         주문 ≥ 2                        표본이 작아도 우연으로 보기 어렵다
승격         주문 ≥ 1 이고 CVR ≥ 필요CVR
부정         주문 0 이고 클릭 ≥ 판정필요클릭
부정         주문 0 이고 광고비 ≥ 손익분기CPA × 3   (CPC 가 오르내려 클릭 수와 어긋날 때)
더 봄        나머지
이미 올림 / 이미 막음   같은 키워드·부정이 이미 있다 (광고구조에서 읽는다, API 아님)
```
정렬은 승격 → 부정 → 더 봄 → … (승격의 순위가 0 이라 `|| 9` 를 쓰면 맨 뒤로 간다 — 실제로 그랬다).

### 5.3 승격 (72P) — [설계]
- 승격줄을 SKU 로 귀속할 수 있을 때만 옮긴다: **광고그룹의 SKU 가 정확히 하나**일 때. 근거는 광고생성계획(SKU목록 1개)·광고그룹(SKU수=1)·광고상품. 후보가 둘이면 답하지 않는다. 나머지는 `[승격SKU]`=`(SKU 모름)` 으로 남긴다.
- SKU 마다 수동 캠페인 하나 `KP EXACT <ASIN>` 를 광고생성계획에 [유형]=수동 · [트랙]=M 으로 넣는다. 승격 검색어가 여럿이어도 캠페인은 하나.
- 반영(72M)에서 키워드는 그 수동 그룹으로, **성공하면 원래 자동 그룹에 같은 말을 부정 정확 일치로 막는다** (안 막으면 같은 말에 우리 캠페인 둘이 서로 값을 올린다).
- 키워드 입찰 = `min(상한 × 0.65, 지금 이긴 CPC × 1.5)` 를 [¥2, 상한] 안으로, 내림. (클릭 1회 주문 1건이 전환율 100% 로 잡히는 것을 막으려고 덮개를 둔다.)
- 실측 (2026-09-04): 승격 1,754줄 중 SKU 를 아는 것 **6줄** (그룹 `Campaign with presets - B0FBLY21B6`, SKU 르네셀토너). 나머지 1,748줄은 옛 몰아넣기 그룹. 이 길은 앞을 보고 만든 것이다 — 우리 전용 캠페인은 SKU 하나짜리라 거기서 나오는 승격은 전부 졸업한다.

### 5.4 트랙 B 예외
- 트랙 B 광고그룹은 **손익분기 × 손해배수**로 잰다. 손익분기로 재면 육성 캠페인의 검색어가 구조적으로 전부 '부정' 이 되어, 순위를 사려고 돈을 쓰던 그 말을 스스로 막는다. 졸업·중단한 줄은 이 예외에서 빠진다.
- 트랙 B 그룹의 승격은 옮기지 않는다 (`(트랙 B — 졸업 뒤에)`). 그 말은 이미 육성 캠페인이 사고 있다.

## 6. 트랙 B — 육성

### 6.1 계산식 (72O `adGrowCalc_`) — [설계], 유도는 검증됨
사람이 준다: 가격 · 마진율(%) · 목표전환율(%) · 주간허용손해(JPY) · 손해배수 r (기본 1.5).
```
손익분기CPA = 가격 × 마진율
CPC상한     = 손익분기CPA × 목표전환율
시작입찰    = CPC상한 × r              일부러 상한을 넘겨 산다. 그것이 순위값이다
주간광고비  = 주간허용손해 × r ÷ (r − 1)
하루예산    = 주간광고비 ÷ 7  (최소 ¥100)
```
유도: 입찰 = 상한 × r 로 사면 `ACOS = 마진율 × r`, 손해율 = `마진율 × (r − 1)`, 광고매출 = 광고비 ÷ ACOS, 주간 손해 = 광고비 × (r − 1) ÷ r. **마진율도 객단가도 약분되어 사라진다 — 잃는 비율은 오직 r 이 정한다.** r=1.5 면 광고비는 허용손해의 3배, 2.0 이면 2배. r=1 은 나눗셈이 안 된다(그건 트랙 A). r=1.5/2.0/3.0 으로 시뮬레이션해 정확히 의도한 손해가 나오는 것을 확인했다.
단, 이 식은 **실제 전환율 = 목표 전환율일 때만** 맞다. 전환율이 예상보다 나쁘면 같은 광고비로 매출이 덜 나와 손해가 커진다. 그래서 매주 실측으로 다시 본다.

### 6.2 대상 제한
- [오가닉순위] 가 광고기준의 [1페이지 순위](16) 안이거나 [목표순위] 안이면 계산·투입 두 곳에서 막는다 (`트랙 A 로`). 순위가 있으면 살 것이 없고, 손익분기를 넘겨 사면 사는 것은 잠식이다. 순위를 안 적었으면 막지 않는다.
- 순위는 검색어마다 다르다. [기준키워드] 로 검색했을 때의 순위를 적는다.

### 6.3 흐름 (메뉴 순서)
```
① 키울 상품 등록     SKU 붙여넣기 → 리스팅에서 ASIN·상품명·가격 채움 → 광고육성 탭
② 트랙 B 계산       API 없음. 위 식. 캠페인명 KP GROW <ASIN> (비어 있을 때만 적는다)
③ 계획에 넣기       승인 ✓ 줄 → 광고육성계획 ([트랙]=B, [유형]=기준키워드 있으면 수동 없으면 자동)
   (광고육성계획에서 한 번 더 승인 ✓ → 처음 한 번 메뉴의 ⑤ 승인분 캠페인 생성)
④ 자동 겨냥 좁히기   자동 캠페인: 대체상품·보완상품 끔 (광고기준 [트랙 B 자동 겨냥])
⑤ 기준키워드 올리기  수동 캠페인: 그 말을 정확 일치로, 입찰 = 시작입찰. 갈아탄 줄이면 여기서 옛 자동 캠페인을 멈춘다
   켜기 — 승인 ✓ 만   여기서부터 돈이 나간다
자동 → 수동 갈아타기  자동으로 시작했다가 기준키워드가 생겼을 때
주간 판정            졸업·중단을 가르고 그 자리에서 멈춘다
```
승인이 두 번인 이유: 육성 표의 ✓ 는 "이 값으로 계획해도 좋다", 계획 표의 ✓ 는 "이 캠페인에 돈이 나가도 좋다".

### 6.4 기준키워드 · 자동/수동 · 겨냥 · 갈아타기 — [설계]
- **기준키워드** = 순위를 사려는 말. 적으면 MANUAL 캠페인에 그 말 하나만 정확 일치로. 비우면 AUTO. 어느 말로 팔릴지 모르면 비우고 2~3주 돌린 뒤 검색어 판정이 골라 준 말을 적는다.
- **왜 자동에 두면 안 되나**: 자동은 그룹 입찰 하나가 남은 모든 말에 함께 걸려서, 손익분기를 넘긴 과입찰이 이길 말에만 걸리지 않는다. 같은 예산이 20개 말에 흩어지면 어느 말에서도 신호가 안 된다.
- **겨냥 좁히기 (④)**: 대체상품·보완상품은 검색 결과가 아니라 남의 상품 페이지에 붙는 광고라 검색어 순위에 기여하지 않는다. 그룹마다 `/sp/targets/list` 한 번 물어 상태를 맞춘다. 살려야 하는데 없으면 만든다. 다시 눌러도 안전.
- **갈아타기**: 아마존이 유형을 못 바꾸므로 새 캠페인 `<옛 이름> KW` 를 광고육성계획에 넣고 옛 줄은 승인을 풀고 표시(`· 수동으로 갈아탐`)를 남긴다. 육성 표는 새 캠페인을 가리키고 옛 ID 는 [이전캠페인ID들] 에. **옛 캠페인은 새것이 상품·키워드까지 갖춘 자리(⑤)에서 멈춘다** — 더 일찍 멈추면 순위 쌓기가 끊기고, 더 늦으면 같은 말에 둘이 입찰한다. 거기까지 못 가면 관제가 하루 안에 잡는다. 시작일과 누적은 이어진다.

### 6.5 주간 판정 (`reviewAdGrow`)
시작일부터 어제까지 캠페인 리포트 한 번. 지금 캠페인 + 이전 캠페인들을 합쳐 누적광고비·누적광고매출·누적손해(= 광고비 − 매출 × 마진율)를 실측.
```
졸업              목표순위 > 0 이고 오가닉순위 ≤ 목표순위
중단              누적손해 > 계획 손해(허용손해 × 주수) × 1.5
돌고 있음         2주 미만 — 판단 유보
중단              클릭 ≥ 50 이고 실제 CVR < 목표의 절반
돌고 있음 (좋음)  클릭 ≥ 50 이고 실제 CVR > 목표의 1.2배
돌고 있음         나머지
```
졸업·중단은 **판정하는 자리에서 바로 멈춘다** (확인 창. 취소하면 표시도 되돌린다). 멈추는 것은 돈을 쓰는 일이 아니라 그만 쓰는 일이라 승인 칸을 두지 않았다. 관제가 매일 한 번 더 본다.

### 6.6 트랙 B 에 없는 것 — 첫 상품 실적을 보고 넣기로 한 것
- **입찰 되먹임**: 시작입찰 한 번 정하고 끝. 실제 CVR 이 목표와 달라도 목표전환율 칸을 덮어쓰지 않고, 새 입찰을 아마존에 보내지도 않는다. 사람이 고치고 ②를 다시 눌러야 한다.
- **예산 소진율**: 하루 예산을 다 못 쓰면 계획한 손해도 안 나고 순위도 안 산다. 판정에 '계획 대비 실제 광고비' 가 없다.
- **순위 추이**: "목표에 닿았나" 만 본다. 몇 주째 순위가 안 움직여도 '돌고 있음'.
- **졸업 뒤 인수인계**: 멈추기까지는 한다. 트랙 A 전용 캠페인으로 옮기는 것은 사람이.
- **수동 전환 시점**: 자동 기준 없음. 사람이 검색어를 보고 정한다.
- 오가닉 순위는 API 로 못 받는다. 사람이 적는다.

| **표를 같이 쓴 대가** — A 의 다시 계산이 B 줄을 지울 뻔, 유형이 A 기준, A 의 건너뛰기가 B 를 막음 | 계획 표 하나 | 트랙마다 표, 실행은 표 목록을 돔 |
| 트랙 B 안내문이 옛 한도 설계("넘으면 A 까지 멈춤")를 말함 | 설계를 바꾸고 문장을 안 고침 | |

공통 교훈 세 가지: **① 판단 단계에서 API 를 읽지 않는다. ② 기본값으로 조용히 떨어지는 자리가 확신에 찬 오진이 된다. ③ 한 표를 두 주인이 쓰면 조건문이 쌓인다.**

## 13. 다시 짤 때 고려할 것 — 내가 보기에 약한 자리

정직하게 적는다. 이 설계를 고집할 이유가 없다.

1. **트랙 A 에 '되먹임' 이 없다.** 캠페인을 만들고 켜는 것까지는 있고, 그 뒤 실적을 보고 입찰을 올리고 내리고 탈락시키는 주간 판정이 없다. 키워드 실적 수집(72G)이 4줄뿐이라 근거가 없어 미뤘다. 새 설계는 여기를 먼저 정해야 한다 — 무엇을 신호로 볼지(ACOS? 판정필요클릭 도달?), 얼마나 자주, 얼마나 크게.
2. **묶음 캠페인의 예산이 틀렸다.** 한 SKU 어치 예산을 20개가 나눠 쓴다. 판정에 20주. 묶음이라는 발상 자체를 다시 볼 만하다 — 묶음은 "값을 따로 매길 수 없는 옛 구조" 를 고치려는 것이었는데, 예산까지 고려하면 전용을 더 늘리는 것이 나을 수 있다.
3. **시장 CPC 가 상수다.** ¥7.7 을 사람이 적는다. 바닥 규칙·성립 불가 판정·안전배수가 전부 이 하나에 걸려 있다. 실측으로 갱신하는 길이 필요하다.
4. **판정필요클릭 219 vs 실제 클릭 1.** 검색어 판정의 통계 기준이 옳아도 표본이 안 모인다. 4주에 0.1% 만 판정선에 닿는다. 검색어 단위 판정이 이 규모에서 맞는 도구인지 다시 볼 것. 그룹 단위·겨냥 단위 판정이 더 현실적일 수 있다.
5. **트랙 B 의 목표전환율은 사람이 찍는 값이다.** 식 전체가 여기에 걸려 있고, 실측으로 자동 갱신되지 않는다. 그리고 순위(입력)와 손해(출력)의 관계를 잇는 것이 없다 — "얼마를 잃으면 몇 위가 되나" 는 아무도 모른다. 순위 추이 기록이 먼저다.
6. **트랙 B 의 승인이 두 번이다.** 육성 표와 계획 표. 표를 가른 대가다. 계획 표 없이 육성 표를 곧바로 실행 큐로 쓰는 설계도 가능하다 (열 대응표만 있으면 된다).
7. **SKU 귀속 문제는 근본적으로 남는다.** 검색어 → SKU 를 모르는 것은 아마존 리포트의 한계다. 우리 전용 캠페인이 늘수록 풀리지만, 옛 몰아넣기 캠페인의 검색어 자료는 영원히 못 쓴다. 옛 캠페인을 언제 접을지가 설계 안에 없다.
8. **관제의 "오류 신호 → 즉시 멈춤" 은 강력하지만 거칠다.** 미승인인데 켜져 있으면 멈춘다 — 사람이 콘솔에서 켠 것도 멈춘다. 의도인지 확인할 것.
9. **모든 것이 메뉴 클릭이다.** 자동으로 도는 것은 관제(매일)와 이어달리기뿐. 주간 수집·판정·반영은 사람이 순서대로 다섯 번 눌러야 한다. 자동화하지 않은 것은 "돈이 나가는 스위치는 명시적 승인" 때문인데, 수집·판정까지 자동으로 돌리고 승인만 사람이 하는 구조가 더 나을 수 있다.
10. **시험 도구가 저장소 밖에 있었다.** node 시뮬레이션이 실수를 여러 번 잡았는데 저장소에 없다. 새로 짜면 시험을 저장소에 같이 둘 것.
